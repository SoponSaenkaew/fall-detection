60 GHz mmWave Radar

HLK-LD6002C: เซนเซอร์เรดาร์ตรวจจับการล้ม 60 GHz Fall Detection Core

วิเคราะห์หลักการทำงาน FMCW, ข้อกำหนดทางไฟฟ้า, และโปรโตคอลสื่อสาร UART Type 0x0E02 / 0x0E0E

สถาปัตยกรรมและหลักการทำงาน FMCW

LD6002C P.3 L.4-11

HLK-LD6002C พัฒนาขึ้นบนชิปเซ็ตเรดาร์ ADT6101P รวมระบบ RF Transceiver ย่านความถี่ 57–64 GHz, สายอากาศไมโครสตริปแบบ 2T2R, หน่วยความจำ Flash 1MB, และแกนประมวลผล ARM® Cortex®-M3 ไว้บนโมดูลขนาดเพียง 25 × 23 มม.

วงจรประมวลผลสัญญาณ FMCW:

โมดูลส่งคลื่นมิลลิเมตรแบบปรับความถี่ต่อเนื่อง (Chirp Signal) ย่าน 58–62 GHz เมื่อคลื่นตกกระทบร่างกายมนุษย์และสะท้อนกลับ จะถูกนำมาผสมกับสัญญาณส่งเพื่อสกัดความถี่บีต (Beat Frequency) จากนั้น ARM Cortex-M3 จะทำการประมวลผล 2D-FFT เพื่อคำนวณระยะทาง ($R$), ความเร็ว Doppler ($v$), และมุมตกกระทบ ($AoA$) ทั้งแนวราบและแนวดิ่ง (±60°) เพื่อสร้าง 3D Centroid Height Tracking

"Suitable for ceiling installation, single person scenarios in small areas of bathrooms and bathrooms." — คู่มือหน้า 3 บรรทัดที่ 10–11

ข้อกำหนดแหล่งจ่ายไฟที่เข้มงวดมาก

LD6002C P.9-10 Sec 8

เนื่องจากคลื่นย่าน 60 GHz มีความยาวคลื่นในอากาศเพียง $\lambda = \frac{c}{f} = \frac{3 \times 10^8}{60 \times 10^9} \approx 5.0\text{ mm}$ การออกแบบกล่องพิมพ์ 3 มิติต้องปฏิบัติตามสูตรฟิสิกส์คลื่นสะท้อน:

ระยะห่างเสาอากาศถึงผิวด้านในกล่อง:
d = (c / 2f) × N = 2.5 mm × N
โดย N = 1, 2, 3... (ระยะที่เหมาะสมคือ 2.5 มม. หรือ 5.0 มม.)
วัสดุที่ผู้ผลิตแนะนำ (Dielectric Constant ต่ำ):
  • ABS: $\varepsilon_r = 2.0 - 3.5$, $\tan\delta = 0.005 - 0.019$ (แนะนำสำหรับงาน 3D Print)
  • PTFE (Teflon): $\varepsilon_r = 2.0$, $\tan\delta < 0.0002$ (ดีเยี่ยมที่สุด)
  • PC / Plexiglass: $\varepsilon_r = 2.6 - 2.9$, ผิวเรียบหนาสม่ำเสมอ
  • ห้ามใช้วัสดุที่มีโลหะหรือสารเคลือบฟอยล์ผสมเด็ดขาด
24 GHz Human Presence Radar

HLK-LD2410C: เซนเซอร์เรดาร์ตรวจจับการมีอยู่ของบุคคล 24 GHz Presence Gatekeeper

วิเคราะห์หลักการตรวจจับ Micro-motion จากการหายใจ, ระบบ Gate ละ 0.75 เมตร, และคำเตือนเรื่องผ้าม่าน

ตรวจจับความเคลื่อนไหวระดับเสี้ยวคลื่น (Micro-motion)

LD2410C P.3 L.4-14

HLK-LD2410C อาศัยคลื่น FMCW ย่าน 24 GHz เพื่อจำแนกสภาวะมนุษย์ออกเป็น 2 ระดับอย่างอิสระ:

Motion State

ตรวจจับการก้าวเดิน, การเอื้อมมือ, หรือการเปลี่ยนอิริยาบถขนาดใหญ่

Stationary State

ตรวจจับการกระเพื่อมของทรวงอกจากการหายใจแม้นั่งนิ่งอยู่บนโถสุขภัณฑ์

โครงสร้างช่วงระยะตรวจจับ (Distance Gates): LD2410C P.8 L.23

ตัวเรดาร์แบ่งระยะตรวจจับออกเป็น 8 Distance Gates โดยแต่ละ Gate มีความกว้างคงที่ 0.75 เมตร (Gate 0 = 0–0.75m, Gate 1 = 0.75–1.5m ... Gate 8 = 6.0m) ซึ่งสามารถปรับตั้งค่าความไว (Sensitivity 0–100) แยกแต่ละ Gate ได้อย่างอิสระ

คำเตือนสิ่งรบกวน (Section 5.5: Installation Conditions)

LD2410C P.12 Sec 5.5

ในคู่มือหน้า 12 มีการเตือนถึงปัจจัยแวดล้อมที่จะทำให้เรดาร์ทำงานเพี้ยนอย่างชัดเจน:

วัตถุที่แกว่งไกวต่อเนื่อง (Continuously Moving Objects):

"Non-human objects that are continuously moving in the sensing area, such as animals, continuously swinging curtains, large green plants facing the air outlet, etc."

คลื่นสะท้อนทะลุด้านหลัง (Back Lobe):

คลื่น 24 GHz สามารถทะลุทะลวงด้านหลังบอร์ดได้ หากด้านหลังมีสายไฟสั่นไหวหรือมีหนูวิ่งในฝ้าเพดาน ผู้ผลิตแนะนำให้ติด Metal shield / Metal backplane ไว้ด้านหลังเพื่อบล็อก Back Lobe

Multi-Sensor Fusion

กลไก Sensor Fusion และการเชื่อมโยงกับโค้ดบน ESP32-S3

ทำไมต้องใช้ 2 เซนเซอร์คู่กัน? และโค้ดใน RadarSensors.h ทำงานร่วมกันอย่างไร

ปัญหาถ้าใช้ LD6002C เดี่ยวๆ

หากไม่มี LD2410C คอยเป็น Gatekeeper วันใดที่มีผ้าขนหนูตกจากราว ไม้กวาดล้ม หรือสิ่งของหล่นลงพื้นตอนไม่มีคนในห้อง เรดาร์ 60 GHz อาจตรวจจับการเคลื่อนที่ตกลงพื้นและยิงแจ้งเตือน False Fall Alert ส่ง LINE ปลุกญาติกลางดึกได้

ปัญหาถ้าใช้ LD2410C เดี่ยวๆ

LD2410C สามารถบอกได้เพียงว่า "มีคนหรือไม่มีคน" (Occupied / Empty) แต่ไม่สามารถวัดความสูงของร่างกาย หรือวิเคราะห์ความเร่งของการทิ้งตัวลงสู่พื้นได้ จึงไม่สามารถทำหน้าที่ตรวจจับการล้มได้เลย

การผสานพลัง (Sensor Fusion)

ระบบใช้ LD2410C เฝ้าประตูห้องน้ำ เมื่อมีคนเข้าห้อง (current_event != "exit") จึงจะ "ปลดล็อกให้อัลกอริทึมล้มของ LD6002C ทำงาน" หากห้องว่าง สัญญาณล้มจะถูกกรองทิ้ง 100% ป้องกัน False Alarm ได้เด็ดขาด

โค้ด Sensor Fusion ใน RadarSensors.h (บรรทัดที่ 145–177)

board-esp32s3/board/RadarSensors.h 
// 1. เฟรมตรวจจับการล้มจาก LD6002C (Type 0x0E02)
if (msgType == 0x0E02) {
  uint8_t is_fall = payload[0]; // 0x01 = ล้ม, 0x00 = ปกติ

  if (is_fall == 0x01) {
    // ⭐ ตรรกะ Sensor Fusion: ประมวลผลล้มเฉพาะเมื่อ LD2410C ยืนยันว่ามีคนอยู่ในห้อง
    if (current_event != "exit") {
      if (!fall_alerted_this_session && current_event != "fall") {
        if (!is_falling_candidate) {
          is_falling_candidate = true;
          fall_start_time = millis();
        } else if (millis() - fall_start_time >= fall_confirmation_delay) {
          current_event = "fall";
          sendEvent("event", "fall", "ตรวจพบคนล้ม (เรดาร์)");
        }
      }
    } else {
      target_event = "exit"; // ห้องว่าง -> กรองสัญญาณทิ้ง ไม่ส่ง False Alarm!
    }
  }
}
Environmental Dynamics

เจาะลึกกรณีศึกษา: ม่านกันแสงแนวตั้ง และน้ำในห้องน้ำ

ข้อเท็จจริงทางฟิสิกส์คลื่นแม่เหล็กไฟฟ้า ตอบคำถามทำไมม่านทำให้เพี้ยน และทำไมน้ำฝักบัวถึงไม่รบกวน

Case Study 1

ปัญหาม่านกันแสงแนวตั้ง (Vertical Blackout Blinds) ทำให้เซนเซอร์เพี้ยน

LD2410C P.12 L.13
กลไกการเกิดความผิดเพี้ยน:
  • Doppler จากการแกว่งไกว: แถบม่านแนวตั้งทิ้งตัวอิสระจากเพดานถึงพื้น เมื่อลมแอร์หรือพัดลมดูดอากาศพัด แถบม่านจะสะบัด (Flutter) เกิดคลื่น Doppler ความถี่ต่ำระดับมิลลิเมตร ซึ่งตรงกับช่วงความถี่การหายใจของมนุษย์ ทำให้ LD2410C ค้างสถานะ OCCUPIED ตลอดเวลา
  • พื้นที่สะท้อนคลื่นมหึมา (High RCS): ม่านกันแสงมักเคลือบสารทึบแสงหนา แผ่น PVC หรือมีชั้นฟอยล์กันความร้อน ซึ่งสะท้อนคลื่นวิทยุได้แรงมาก เสมือนกระจกเงาคลื่นวิทยุ บดบังสัญญาณสะท้อนจากมนุษย์
  • Point Cloud หลอกการล้มใน LD6002C: ม่านพาดจากเพดาน ($Z=2.5\text{m}$) ลงมาถึงพื้น ($Z=0\text{m}$) เมื่อม่านสะบัด จุดสะท้อนจะรูดจากบนลงล่าง อัลกอริทึมใน LD6002C จึงคิดว่า "มีคนทิ้งตัวลงสู่พื้นอย่างรวดเร็ว = คนล้ม!"
แนวทางแก้ไข 3 ระดับที่ได้ผลจริง:
  1. การแก้ไขทางกายภาพ (ได้ผลทันที): ตรึงชายม่านด้านล่างเข้ากับวงกบหน้าต่างด้วยแม่เหล็ก หรือเทป ไม่ให้แถบม่านพริ้วไหวตามลม หรือปรับทิศทางบานสวิงแอร์ไม่ให้เป่าปะทะม่าน
  2. การปรับจูน Gate ใน LD2410C: ใช้แอปมือถือ HLKRadarTool กำหนด Max Detection Gate ให้หยุดก่อนถึงระยะม่าน หรือลดค่า Sensitivity ใน Gate ที่ตรงกับม่าน
  3. การปรับหน่วงเวลายืนยันล้มในโค้ด: ปรับแก้ค่า fall_confirmation_delay ใน SystemConfig.h จากเดิม 0 มิลลิวินาที ให้เป็น 2000 - 3000 ms (หน่วง 2–3 วินาที) เพื่อกรองสัญญาณสะบัดชั่วคราวทิ้ง
